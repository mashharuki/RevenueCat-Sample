# memo_app + api — fullstack practice app

SwiftUI iOS client (`memo_app/`) + Cloudflare Workers/Hono backend (`api/`), connected via Firebase Auth (Google Sign-In) + RevenueCat entitlement gating on memo count.

Spec status: `.kiro/specs/memo-app/spec.json` phase=`tasks-generated`, all 3 approvals (requirements/design/tasks) true. Git log shows all task groups completed through post-release fixes (`cd96554` "mark all task groups complete", plus later JWKS-URL fix and deploy-doc additions).

## Resources
- Firebase project `memo-app-shipaton`; iOS bundle id `com.haruki.MemoApp`. Only Google Sign-In auth provider is managed via `firebase.json` — no Firestore/other Firebase services used.
- Cloudflare Worker `memo-app-api` (`https://memo-app-api.avp-104-106-107-a78.workers.dev`), D1 db `memo-app-db` (table `memos`), secret `RC_SECRET_KEY` (RevenueCat REST API key).
- `wrangler.jsonc` vars: `FREE_TIER_MEMO_LIMIT=20`, `RC_ENTITLEMENT_ID=memo_premium`, `FIREBASE_PROJECT_ID=memo-app-shipaton`.
- `api/src` layout: `billing/revenueCatClient.ts` (RC REST client), `memos/{repository,service,routes}.ts`, `middleware/firebaseAuth.ts` (validates Firebase ID token via JWKS, checks `iss`/`aud` against `FIREBASE_PROJECT_ID`), `errors.ts`, `types/env.d.ts` (generated by `npm run types` — do not hand-edit).

## Non-obvious gotchas (from tasks.md Implementation Notes / real incidents)
- `npm run deploy` (=`wrangler deploy`) does NOT apply D1 migrations. Omitting `wrangler d1 migrations apply memo-app-db --remote` before deploy caused a real prod incident on 2026-07-27 — always migrate remote D1 first, then deploy.
- `firebase.json` `authorizedDomains` must NOT include protocol/port (`localhost`, not `http://localhost:9090`) — including one causes immediate `[firebase_auth/unauthorized-domain]` failure on Google Sign-In.
- `firebase deploy --only auth` is not a dedicated destroy command — it just re-applies whatever `firebase.json` currently contains. To disable a provider: edit `firebase.json` first, then run the same deploy command.
- XcodeGen `project.yml` permanently declares `GIDClientID`/`CFBundleURLTypes`/`GoogleService-Info.plist` — running `xcodegen generate` after adding/removing files in `Sources/` will NOT wipe these.
- Test suite (unit + `@cloudflare/vitest-pool-workers` integration) never exercises the real deployed Worker, real Firebase JWKS endpoint, or real remote D1 — only local/stubbed. Route-specific bugs (wrong JWKS URL, unapplied remote migration) only surface via real-device/deployed verification.
